# Processus de publication

1. Modifier le code et le contexte associés.
2. Exécuter typage, tests, build, audit et détection de secrets.
3. Appliquer les migrations sur l'environnement de preview.
4. Déployer une preview protégée.
5. Tester les parcours critiques sur ordinateur et mobile.
6. Corriger et recommencer jusqu'à réussite des portes définies.
7. Demander l'autorisation de promotion si elle expose une nouvelle version.
8. Promouvoir exactement l'artefact testé.
9. Vérifier login, actions, erreurs, performance et journaux après promotion.
10. Revenir à la version précédente si une porte échoue.

Une publication n'est jamais déclarée terminée sur la seule base d'un build réussi.
